## Quickstart

In order to quickly get started with the project follow these steps:

1. Clone the repository:
    ```bash
    git clone git@github.com:mickkc/baby-tools-world.git
    cd baby-tools-world
    ````
2. configure required application environment variables
    ```bash
    # Copy the example .env file:
    cp example.env .env

    # Edit it:
    nano .env
    ```
3. Build and start the container using Docker Compose:
    ```bash
    docker compose up -d --build
    ```
4. verify the application is running by visiting `localhost:8000`


## Tags

Tags can be applied to products using the admin panel, located at `/admin`. Each product can have multiple tags.

These tags are shown in the product page and if there are no tags available, a default placeholder text is shown.
Admins can also filter products by their tags in the admin panel, making it easier to group and find them.

### Implementation steps:

#### Models & Database:

My first task was to implement a new feature into the already existing application:

- I created a new `Tag` model that contains a name, the creation date and the last update timestamp
- I also added some metadata used by the administration UI:
  - `ordering = ["name"]` to sort tags by their name
  - `verbose_name_plural = "Tags"` to correctly display the model name

```python
class Tag(models.Model):
    name = models.CharField(max_length=30, unique=True, null=False, blank=False)
    created_at = models.DateTimeField(auto_now_add=True, editable=False)
    updated_at = models.DateTimeField(auto_now=True, editable=False)

    def __str__(self):
        return self.name

    class Meta:
        ordering = ["name"]
        verbose_name_plural = "Tags"
```

Then, I added a many to many relationship to the product model.
This means that every product can have any amount of tags, and each tag can be applied to any amount of products.

```python
class Product(models.Model):
  ...
  tags = models.ManyToManyField(Tag, blank=True)
```

:::note
`blank=True` means that a product can also have no tags at all.
:::

... and added it as a view in the admin interface:

```python
@admin.register(Tag)
class TagAdmin(admin.ModelAdmin):
    list_display = ("name", "created_at")
    search_fields = ("name",)
```

I also added filters to the admin view, so that products can be filtered by their cantegories and tags:

```python
class ProductAdmin(admin.ModelAdmin):
    ...
    list_filter = ("category", "tags")
```

After modifying the models, I created a new migration. This migration automatically adds the underlying tables and
columns to already existing databases, so the new feature can be used on already running instances of the software
without needing to manually ajdust the database schemas beforehand:

```bash
python manage.py makemigrations
```

#### Shop UI:

After the models were implemented and could be set in the admin UI, they needed to be displayed in the shop, so that
customers could see them.

For that, I added a new section to the product page, listing all product tags:


```html
<div class="mb-3">
  <strong>Product-Tags:</strong>
  <br>
  {% if product.tags.exists %}
    {% for tag in product.tags.all %}
      <span class="badge bg-secondary">{{ tag.name }}</span>
    {% endfor %}
  {% else %}
    <span class="fst-italic text-muted">no tags available</span>
  {% endif %}
</div>
```

This either shows each tags as a badge, or the text `no tags available` in case the product does not have any tags.


## Updating the rating system

Another task was changing the rating system. Before, the rating and comment inputs where always prefilled if the user
rated and commented a product. I changed it so that they are no longer prefilled, and creating a new rating would
overwrite any previous rating submitted by the user.

There was also a unit-test for the old functionality, which I updated to check that the inputs are empty, regardless
if a previos rating exists or not.


## Containerization

The last task was containerizing the application using Docker Compose.

There was already a `Dockerfile` included in the project, so all I needed to do was create a `docker-compose.yml`:

```yaml
services:
  btw:
    build: .
    ports:
     - "8000:8000"
    volumes:
     - media:/app/src/media
     - database:/app/src/db.sqlite3
    env_file: .env
    restart: unless-stopped

volumes:
  media:
  database:
```

- The `build: .` option tells docker to use the `Dockerfile` in the repository root to build the image
- `ports:` specifies the port mapping in the format `host:container`. The application is running on port `8080`, so the
  second part must be `8080`. The first part, which specifies the port on that host, could be anything, but I also used
  `8080` to keep it simple.
- `volumes:` creates two volumes that persist the uploaded media (product images) and the database, so they don't get
  lost when the container restarts. These volumes are defined at the end of the file.
- `env_file:` defines the environment variables set inside the container, loaded from the `.env` file.
- `restart: unless-stopped` means that the container gets automatically restarted on errors, unless explicitly stopped
  using `docker stop`.
